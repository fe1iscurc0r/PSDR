# HMC1023 的驱动"能不能补"——判定（2026-11-04）

问题：这颗可编程低通（U287）在固件里零引用，硬件上到底差什么？能不能补？

口径：**只判定，不动固件**（本仓边界：不改 `Source*/`）。所有"板上"事实来自网表与 32 脚核对手册
（`docs/PSDR-HMC1023-pinmap-check.md`）；"固件"事实来自 `Source_F7/` 只读。

## 1. 已经具备的（读得）

| 条件 | 状态 | 出处 |
|---|---|---|
| SPI 总线 | ✅ `SCK`/`SDI` 与数字电位器 U15 **共用**（U121.52/54），`SEN`(CS) 与 `SDO` 是 HMC1023 专用（U121.51/53 → U287.15/13） | 网表四条 `FILTER*` 网 |
| 供电（数字/模拟/校准） | ✅ `DVDD`(16)、`VDDQ`(2,4)、`VDDi`(21,23)、`VDDCAL`(22) 全在 `LPF_5V` | 网表 |

| 手册 | ✅ 原件在手（v01.0113，Table 6 已逐脚对完） | `PSDR-HMC1023-pinmap-check.md` |

## 2. 缺的三件（都是读得，不是推测）

| # | 缺口 | 证据 | 补它需要什么 |
|---|---|---|---|
| **A** | **`VDDBG`(28) 没有供电**——只挂了去耦 `C292`，没有任何电源馈入 | 网表 `$$$15137` 只有 `U287.28` + `C292.1`；手册要求 "Bias 5V Supply" | **一根飞线/一处跳线**把 `LPF_5V`（pin 22 同网）接到 pin 28 或 `C292` 热端；rev-B 里则是在板上补一段铜 |
| **B** | **`CLK1A` 不由固件配置**——Si5338 的 CLK1 频率/使能在代码里找不到（全树只写 `MULTISYNTH0`） | `Source_F7/src/i2c.c` 只有 `MULTISYNTH0`；`CLK1A` 接 `FILTER_CAL` | 取决于芯片 **NVM 默认配置**：要么 NVM 里已有 20–80 MHz，要么需要改固件/重烧 NVM（两者都超出"只读"边界） |

## 3. 判定

* **在这块 2.6.1 板上"只靠固件"补不出来**：A 是硬件断点（没有供电），C 是代码空白，B 不在固件控制里。
* **rev-B 上"能补"，代价可估**：补一段 `LPF_5V → VDDBG` 的铜（A）+ 确认/写入 Si5338 的 CLK1（B）+
  写 HMC1023 驱动（C）。三者里只有 C 是软件工作量；A/B 是硬件/配置。
* **不补驱动也能做的最小实验（台架，需飞线）**：
  1. 用外接 5 V 直接从 `C292` 热端给 `VDDBG` 供电（或从板上 `LPF_5V` 飞线）；
  2. 用信号源给 `CALCK`（经 `C283` 那一侧）送 **20–80 MHz、50% 占空比**的时钟；
  3. 用 USB-SPI 工具直接驱动 `SCK/SDI/SEN/SDO`（绕过 MCU，因为总线与 U15 共用，注意别和 MCU 抢）；
  4. 扫频测 `FILTER_IN_P/N → FILTER_OUT_P/N` 的幅频响应，与"不做校准"的预期对照。
  这条路径**不需要改固件、不需要改板**，只需要飞线与仪器——是验证"这颗件值不值得保留"的最短路径。

## 4. 手册侧要点（写驱动时要用的）

* 截止频率档位是**离散码**（5–72 MHz 区间）；校准由寄存器 `04h` 触发，`05h` 读回的校准结果单位是 ps；
  `CALCK` 要求 20–80 MHz、占空比 50%±10%；用户校准后精度指标见手册（Table 里标 ±2.5% 一档）。
* 这些数字来自 v01.0113；具体寄存器位定义在手册的寄存器表里，写驱动前需逐位抄一遍（本仓未抄，避免错位）。

## 5. 与既有结论的关系

* #16 的"前放/LPF 没跑起来"：**HMC1023 这一半现在有硬件级解释**（VDDBG 无电 + 无驱动）；
  另一半（U304/SXB）仍是"器件身份 + 带宽"问题，见 `docs/PSDR-alternates-proposal.md`。
* Q 通道自环（`docs/PSDR-HMC1023-pinmap-check.md`）：即使补上驱动，也只有 I 通道可用；不要按"双通道"设计。
