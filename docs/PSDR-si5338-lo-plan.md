# Si5338（U241）与"正交 LO / Fvco÷8 双频约束"的核对（2026-11-04）

问题（来自外部手册核对 findings §2.3）：Si5338 Rev 1.6 规定 MultiSynth 输出 `5 … Fvco/8`，
**同一 VCO 下只有 Fvco/4 与 Fvco/6 两档可以高于 Fvco/8**。我们的方案是"LO = 2×RX、I/Q 由触发器 ÷2 得到"——
若需要两路都落在 >Fvco/8 区，是否撞上"只有两个"的限制？

**结论先说：不撞。** 按固件现在写死的 VCO 值，`Fvco/8 = 355 MHz`，而 CLK0 的上限是 **350 MHz**——
**永远不会进入 >Fvco/8 区**，所以那条"只有两个输出可以高"的限制从未被触发。
下面给全部读数与算式，另外带出两处新发现（一处可能越规格、一处是 CALCK 的来源问题）。

---

## 1. 三路输出分别接了什么（读得，网表逐脚）

| 输出 | 网名 | 板上落到 | 用途 |
|---|---|---|---|
| `CLK0A` / `CLK0B` | `$$$5510` / `$$$5513` | `C265.1` / `C267.1`（交连电容）→ `SY100EP52V` 两只交叉耦合 | **LO**：先 2×，再由触发器 ÷2 得到正交 I/Q |
| `CLK1A` | `FILTER_CAL` | `C283.2` → `U287.11`（`CALCK`） | **HMC1023 的校准时钟**（手册要求 20–80 MHz、占空比 50%±10%） |
| `CLK2A` | `F_SYNTH_CAL` | `U121.39`（PE9 / TIM1 通道） | **回到 MCU 做频率测量/校准**，不是给外设的时钟 |

（另：`IN1/XTAL`、`IN2/XTAL` 接 26 MHz 参考；`VDD*`/`VDDO*` 全在 `+3V3_CPU`。）

## 2. 固件里实际写进去的数（读得，`Source_F7/src/i2c.c`）

* `vcoFreq = 2840000000`（`:727`）——**2.84 GHz**；
* `setFreq()`：先 `frequency *= 2`（`:762`，给 ÷2 触发器补回来），随后
  **`if (frequency < 5000000) return;` / `if (frequency > 350000000) return;`**（`:764-765`）
  ⇒ 可调范围 = **调谐 2.5–175 MHz / CLK0 5–350 MHz**，超出**静默不调**；
* MultiSynth 参数：`integer = vcoFreq / frequency`（整数除），`remainder = vcoFreq % frequency`，
  再把 `remainder/frequency` 这一分数**同除 2** 直到分母 ≤100 kHz（`:797-801`，分数值不变，只是适配寄存器位宽）；
* **只写了 `MULTISYNTH0`**（`:521` 定义、`:808` 调用）。全树搜索 `MULTISYNTH` **没有 1/2/3** 的写入
  ⇒ CLK1/CLK2 的频率**不由固件设定**（见 §4 的发现 2）。

## 3. 约束核算（算得）

`Fvco/8 = 2.84 GHz ÷ 8 = 355 MHz`；`Fvco/4 = 710 MHz`；`Fvco/6 ≈ 473.3 MHz`。

| 调谐 f (MHz) | CLK0 = 2f (MHz) | 是否 > Fvco/8=355 | 所需分频 `vcoFreq/CLK0` |
|---|---|---|---|
| 2.5 | 5 | 否 | 568 |
| 7 | 14 | 否 | ≈202.9 |
| 14 | 28 | 否 | ≈101.4 |
| 28 | 56 | 否 | ≈50.7 |
| 50 | 100 | 否 | 28.4 |
| 100 | 200 | 否 | 14.2 |
| 144 | 288 | 否 | ≈9.86 |
| **175（上限）** | **350** | **否（350 < 355）** | ≈8.11 |

* **全量程都 ≤ Fvco/8** ⇒ MultiSynth 用普通分频即可，**不需要** Fvco/4 或 Fvco/6 那两档；
* 因此"同一 VCO 只有两个输出可高于 Fvco/8"这条**不构成约束**——我们连一个都没有；
* `R≠1 时相位对齐失效` 那条也不适用于我们：**正交不是靠 Si5338 的相位对齐做的**，是外部触发器 ÷2 得到；
* 即使把 VCO 压回规格上限 2.8 GHz（`Fvco/8 = 350 MHz`），CLK0 的 350 MHz 只是**正好等于**边界，
  仍不算"高于"；只有 VCO 低于 2.8 GHz 时 CLK0 才会越界，而那时**也只有 CLK0 一路**越界
  （CLK1 ≤80 MHz、CLK2 是测量输入），"最多两路"的额度仍然够用。

## 4. 核算里冒出来的两处新发现（都不是这次的结论，但要记账）

1. **固件把 VCO 写成 2.84 GHz，超出 Rev 1.6 的 2.2–2.8 GHz 上限。**
   可能性有三：① 作者参考的是旧版手册；② 实购的 Si5338 变体/批次允许；③ 代码里的 `vcoFreq` 只是"假定值"，
   芯片实际 VCO 由 NVM/寄存器决定，二者不一致时**输出频率会按比例偏**（例如实际 2.8 GHz 时，
   所有输出会比请求值低约 1.4%）。
   **这件事在 M3 一上电就能判死**：量 CLK0（或用一个已知调谐频率对一台已知信号源比对），
   看实际是不是请求值；对不上就要查 NVM 与 `vcoFreq`。**只记录，不改代码。**
2. **CLK1（HMC1023 的 `CALCK`）与 CLK2 不由固件设定。** 全树只写 `MULTISYNTH0`。
   这两路要么来自芯片的**工厂 NVM 默认配置**，要么根本没启用。
   ⇒ HMC1023 就算将来补上驱动，**校准时钟是否存在取决于 NVM 内容**；
   这与我们已记的"固件零引用 HMC1023"是两条独立缺口，别混成一条。

## 5. 对 rev-B / 固件移植的含义（不涉及改码）

* 时钟方案本身**没有被 Fvco 约束卡住**，rev-B 不需要为 LO 换架构；
* 若将来把 VCO 改到规格内（≤2.8 GHz），**要重跑这张表**：只要 CLK0 仍 ≤ Fvco/8 就安全；
* 若将来想把 CLK1/CLK2 用起来（例如给 HMC1023 供 20–80 MHz），
  要把它们一起纳入"同一 VCO 下输出频点"的核算——本表已证明它们远低于 Fvco/8，**不占那两档额度**。
