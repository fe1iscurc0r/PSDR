## 4. 2026-11-10 作者台架实测（上游一手，我方未复测；G1/G2/G3 状态不变）

来源：作者 @MichaelRColton 2026-11-10 台架更新，#16 评论 id 6756908658（02:06）、6758050579（03:22）、
6759861284（05:30）、6761445468（07:16）与 #19 评论 id 6756908997、6758088245、6760639011
（逐字存档在 `docs/PSDR-upstream-threads.md`）。证据强度＝**作者台架实测自述**，
不是我方仪器数据；凡涉及"本板"的验证仍走 G2/G3。固件载体＝当日上午的 `fix/hmc1023-lpf`，
**当日 03:25 起已并入 master（现行固件）**；**我方镜像固件冻结，以下均为记录不是改动**。

1. **VDDBG 缺口被台架证实并修复**：作者在 2.6.1 板上从 C292.1 飞线到 `LPF_5V`，芯片即活，
   SPI 读回 reg0 = `0x114080`。与我方网表结论（D-02）及无射频测试板的蚀刻修复互为独立印证。
   **当日下午补充实测（未改板）**：-60 dBm@7.000 MHz 入天线口，bypass 档高出噪底 17–22 dB，
   走 HMC1023 则无论增益开关都淹没（0 dB）⇒ 飞线确属必需；且**未改板 SPI 照样应答、配置寄存器照样读回**
   ⇒ **寄存器读回不能验证飞线/蚀刻修复，必须过信号**（我方上电判据已按此改，见 bringup-checklist 附录）。
2. **寄存器坑**：reg1 必须写 `0x1C`；写 `0x12` 会清掉 I/Q 通道使能位、芯片什么都不传
   （作者修于 `6ce8a3b`）。对账发现：我方 `tools/hosttest/hmc1023_seq.c:33` 校准时写 reg1=`0x0002`
   （RC cal enable）后**没有恢复 `0x1C` 的收尾步骤**——序列停在 poll reg8。若按此序列上板，
   校准后需补写 reg1=`0x1C` 才能传信号（工具侧待办，不碰固件）。
3. **mux 真值表（信号发生器实测）**：`ch = (S1<<1)|S0`，两只 mux（U211/U298）共用选择线：
   0＝外部滤波器排针位（未贴）、1＝bypass（旧 `signalPath()` 恒写的状态）、
   2＝HMC1023 接收方向、3＝发射方向。⇒ G3 子板实验要插的档位是 **ch0**，此前纸面推断被实测确认。
4. **增益链路**：板上两通道级联（I 输出→Q 输入，即 pinmap-check §2 的交流耦合跨接），
   每通道约 +10 dB、混频器前合计约 **+20 dB**。分支加了机内 "+20dB" 菜单开关与控制台 `H` 命令。
   默认寄存器下 **-100 dBm CW 在瀑布上勉强可见**；作者未做正式 MDS（等衰减器），**不引用灵敏度数字**。
5. **上电默认路径（当日两次变更，以晚为准）**：02:06 版本开机走 HMC1023（mux ch2），无飞线板需 `M1` 回 bypass；
   **03:22 作者改了默认**：菜单项改为 **LPF 三档 Bypass / 0 dB / +20 dB**（控制台 `l0`/`l1`/`l2`），
   **开机默认 Bypass**，未改板也能正常接收；有飞线的板手选 0 dB/+20 dB，选择会记忆。`M1` 警告作废。
   ⇒ 我方无射频板（有蚀刻修复）刷现行固件后须**手选 l1/l2** 才走 HMC1023。
6. **CALCK 时钟缺口已在上游补上**：旧固件从未写 MultiSynth1，CLK1A 停在复位默认 ÷4（过快不可用）；
   分支写 MS1 ÷71 → **40 MHz**（`24f113d`），目前常开，"仅校准时开"在作者 to-do；CLK2A→PE9 仍未配置。
   ⇒ §1 表里"CALCK 依赖 NVM 上电状态"的担忧在**该分支**上已不成立；我方冻结镜像仍带旧行为。
7. **对 G3 的影响**：HMC1023"能用、有约 +20 dB"已是作者台架事实，6 段 LC 子板要证明的是
   "带通比它更好"而不是"它能不能用"；A/B 口径不变（同一台机器），仍等我方板子 + 仪器。
8. **基线变更（当日 03:25）**：`fix/hmc1023-lpf` 已并入 **master**（连同 PR #18），master 是现行固件；
