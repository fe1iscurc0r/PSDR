# PSDR 2.6.1 上电前检查表（M3 准备，2026-11-02）

这份表**只做两件事**：把"板子到手后按什么顺序通电、测哪里、判据是什么"先钉死；
把不需要实物就能确定的东西（测点位置、网络归属、控制脚）从设计数据里算出来。

它**不包含任何固件改动，也不包含射频前端的修改**（边界：#16/#6 的 preamp 与低通
不归本项目动；#8/#9 的固件源码冻结）。每条都留"实测值"和"结论/SKIP 原因"两栏，
跑不了就写 SKIP，不许写"应该没问题"。

数据全部来自 `Hardware/PSDR.asc`（`468dc41` 的 PADS Layout ASCII），
经 `tools/pads_asc_netlist.py`（391 件 / 278 网 / 1132 脚）与
`tools/pads_asc_placement.py`（391 个贴装项，含 42 个单焊盘点位）。

| 4.5 | 滤波切换探针 | TP `E_FILT_IF_N/P`、`E_FILT_RF_N/P`（底面 4 点） | 滤波器插损扫描 | | |

**#9 相关的现成事实**（本表可直接验证，不需要改代码）：U121 的 **PA0 既是 STM32 的
standby 唤醒脚，又是 `AMP_SWITCH_A`——也就是前置放大器 RF 开关 U16 的 V1 控制脚**。
作者说 `EnterSTANDBYMode()` 只能等 PA0 的上升沿；那么待机时 PA0 的驱动状态会同时
决定 U16 停在哪个触点。4.1 在"待机"态记录 PA0 电平，就是在验证这个假设。

## 5. 无实物时的处置

本表每一条在硬件到位前都填 `SKIP：无 2.6.1 实物`。不允许因为"设计数据看起来对"
就把某条记成通过——设计数据能证明的只有位置和网络，电气行为必须由实测得出。
