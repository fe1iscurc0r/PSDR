## 提示词正文（从这里开始贴）

你在替一个开源 HF SDR 项目（PortableSDR / PSDR 2.6.1）做**器件级参数核对**。
你没有仓库，所有需要的板上数据都在附件 `TASK_C_ic_context_all.md` 里。

### 输入文件是什么

* 附件是**一块真实 PCB 的网表**，从 PADS Layout ASCII 源文件 `Hardware/PSDR.asc` 机读导出，
  不是画出来的原理图。每个 section 一只器件，表头四列：
  `pin | pin name | net | other pins on the same net (refdes(part_type).pin)`。
* 坐标/单位这类信息这轮用不到；`$$$…` 开头的 net 名是 PADS 里的**未命名导线**，
  表示一个电气节点，本身没有含义，不要试图解读。
* 邻居写法如 `C13(CAP_2603=100n).1`：**括号里是这只件的类型与该位的值**。
  值有两种标注：`=VALUE` 是板文件与 BOM 一致；
  `=VALUE CONTESTED: BOM 0R, board file 1k0` 表示**两个来源不一致**，
  这种情况下**两个值都要算一遍**并把结果并排给出，不许挑一个当准。
* 有的 pin 在表里根本没有行 ⇒ 那只件的该脚在板上**未连接**（不是数据缺失），照此判断即可。

### 硬性出处规则（违反即视为未答）

1. 每个结论必须带：**手册文件名 + 修订号 + 页码或表号 + 一句英文原文摘录**。
   没有这四样就写 `信息不足` 并说明缺什么，**不要用"典型值/常识/通常"补**。
2. **只接受厂商原始 PDF 或厂商官网页面**。不要引用论坛帖、第三方商城参数表、AI 汇编。
3. 计算过程要写出来：公式（带原文出处）→ 代入的板上值（注明来自附件哪一行）→ 结果与单位。
   只给结果不给代入过程的行，我们只能退回重算。
4. 遇到 `=VALUE CONTESTED` 的元件：**两个值各算一遍**，并写清结果差多少、
   这个差别会不会改变"能/不能工作"的结论。不要替我们选值。
5. 涉及电压轨（`V_SUPPLY`、`+3V3_CPU`、`+5V_BOOST` 等）时，如果附件里能由分压电阻算出轨压，
   就写"算得 X V（由 R_a/R_b 与反馈电压 Y 推得）"；**算不出来就写"板上无依据"**，
   不要引用外部项目（mcHF/UHSDR 等）的电压当本板事实。
6. 不猜测器件型号。附件 section 标题写的是板上封装名，可能与真实采购件不同
   （已知 U304 名为 `HMC482ST89`、BOM 买的是 `SXB-2089Z`）；
   标题下有 `Premise check` 行，**如果你判断器件对不上，停下并报告矛盾，不要接着算**。

### 输出格式

一张 Markdown 表，列固定为：

`器件 | 引脚/话题 | 手册公式或判据（含页/表 + 英文原文摘录） | 板上代入值（含来源行） | 结果 | 判定 | 出处强度`

* `判定` 取值：`一致` / `不一致（差 X）` / `信息不足（缺 Y）` / `前提矛盾，未答`。
* `出处强度` 取值：`原厂PDF` / `官网页面` / `镜像文本` / `无`。
* 表后再加一节"本轮新拿到的手册直链清单"（文件名 + URL + 你看到的修订号），
  以及一节"你认为我们必须上板才能定的项"，每项写要量什么、判据是什么。
* 报告用中文或英文都行，**但英文原文摘录必须保持原样不译**。
