# 提示词 · 把 PSDR 做成一份"编年史"网页（2026-11-04，可直接粘贴）

用法：整段贴给执行方（可以是没有本仓库上下文的账号）。**附件按 A 档必需、B 档可选**上传；
他不需要联网抓数据——所有素材都在附件里，页面里的每个数字都必须能在附件里回查到。

设计前提说明（我方侧，不必贴出去）：这个页面将来可能被公开，所以里面写死了三条禁区——
**不放替代件/降本/国产化内容**（那些只留 fork，不进对外场合）、**不冒充官方**、
**待测数值不许画成仪表读数**。这三条是我方既有边界，不是审美偏好，别删。

## 提示词正文（从这里开始贴）

给一个开源短波收发信机项目 **PortableSDR（PSDR）** 做一份**编年史式的介绍网页**。
它是一个真实存在过的硬件项目：2014 年开工、2016 年出 2.6.1 版板子、约 100 台、之后停摆，
2026 年被第三方接手做了资料抢救与文档化。页面要同时做到三件事：
**把人讲清楚**（谁在什么时候说了什么）、**把机器讲清楚**（它到底是什么架构）、
**把证据边界讲清楚**（哪些是事实、哪些是推测、哪些还没测）。

### B. 内容结构（按这个顺序做，不许漏"诚实清单"）

1. **首屏**：一句话定义 + 三个硬数字。定义必须用作者原话（附件 `PSDR-upstream-threads.md` 里的视频文稿）：
   *"The PortableSDR is a pocket sized, two way shortwave radio."*
   三个数字只能用：`391` 个件 / `278` 个网络 / `1132` 个连接引脚（源：网表，chronicle 第二纪有注）；
   `约 100 台`（作者 2025-10-28 在 #16 的原话 "about 100 units"）；
   `2014 → 2026`（跨度）。**不许**写输出功率、灵敏度等未在附件里出现的数字。
2. **年表（页面的主体）**：一条可滚动的竖向时间线，条目取自 `PSDR-chronicle.md` 第一纪与第一纪补，
   每条格式固定：**日期 · 发生了什么 · 谁 · 出处（`#issue` 或 commit sha）**。
   至少要包含：2014-07-15 #1/#2 开、2014-09-28 `PSDR2 Guide.pdf` 创建、2014-10-15 滤波系数表进仓、
   2016-04-18 2.5 原型（"no frequency synth yet"）、2016-07-31 `468dc41` 2.6.1 PCB complete、
   2016-11-08 装配说明创建、2017-01 pwarren 的 Linux 编译与 OFF/待机、2017-01-06 #6/#7/#8/#9 四帖、
   2017-01-15 作者热成像结论（最大功耗 `U241: SI5338`）、2018-06-21 F7 hex、2019-05-24 FreeRTOS 重建树、
   2021-01-30 #13/#14、2021-02-06 #16、2021-02-19 Jeff 在 DigiKey 之外找到两只断供件、
   2021-03-05 上游最后一次合并、2021-12-06 作者承认前放/LPF 没跑起来、
   2021-12-09 DM2NT 指来 UHSDR 的 HMC1023、2025-10-28/30 回访与"欧洲买不到 MASWSS0129"、
   2026-08-19 接手者第一次请求接手、2026-09-11 MIT 落地、2026-10-31→11-03 PR #17 合并、
   2026-11-01 PR #18、2026-11-02/03 新 issue。
3. **声音墙（人物卡）**：同一条时间线上不同的人说的话，原话 + 身份 + 日期 + 出处。
   至少六位：Michael Colton（作者）、Paul Warren `@pwarren`（2017 年把固件在 Linux 上编出来的人、
   **自述是出过钱升级"免焊"套件的众筹支持者**）、Jonas `@sanamon`（第二条 Linux 构建路线；
   **"this thing is deaf as a brick"、−70 dBm/"差 50 dB" 这句经验的原始作者**）、
   Jeff Benson `@jeffersonbenson`（2021 整理 + 2026 推动 MIT）、DM2NT（把 UHSDR 引进线程的人）、
   接手方 `@fe1iscurc0r`（2026，自述学生 + 中国 A 类业余无线电操作证）。
   **署名只用 GitHub 用户名**；不写邮箱、不写真名、不写所在地（那些信息页面不需要，也不要联网去补）。
4. **机器本身**：一块 4 层板 + Tayloe 采样开关 + AD8302 构成 VNA + HMC1023 可编程低通 +
   Si5338 时钟 + STM32F746。只讲附件里有的：`1194` 个焊盘 / `461` 个钻孔、
   三片 DPDT `U16/U24/U30`、`E_FILT` 四个直插焊盘（外接滤波插槽）、`U30` 的 pin 6 是空掷位。
   建议做一张**内联 SVG 的链路示意**（天线 → DPDT → HMC1023/mux → 混频 → ADC/MCU），
   节点标注必须来自 `PSDR-HMC1023-netlist.md`/`open-data-gaps` 的位号，**不许自己画未存在的模块**。
5. **作者留下的六份材料**（`documentation-archive`）：那页没写完的 2014 VNA 说明最动人，
   原文照引他留下的自问：*"Whre is it controlled in code?"*、*"THEN WHAT HAPPENS?"*、
   *"TODO: What are C68 and 111 for again?"*（拼写保持原样，这是历史的一部分，不要"顺手改正"）。
6. **接手这七天**（第二纪）：做了什么、量了什么、算出什么。
   必须给出那条反转结论：**只有 U304 子图算"局部"，DPDT/HMC1023 二跳就铺满全板**；
   以及 **124 / 391 / 267** 这组数（源 `zones_summary.md`）。
7. **诚实清单（必须有，放在显眼处）**，三栏：
   *声称的* / *不声称的* / *待测的*。底本是 `README.fork.md`。必写的几条：
   没有板子、没有仪器，**全页没有任何实测值**；`+3V3_CPU` 2.898/3.012 V 是**算得**不是量得；
   U304 带宽 5–2500 MHz 只是**镜像文本级**、原件取不到；
   MASWSS0129 原件在厂商 CDN 上 404（同路径两件兄弟件 200）；
   Qorvo 产品页我方出口是 **429 限流**，所以页面只能写"检索不到"，不能写"已撤档"。
8. **我们撤过的话**（第四纪那 11 条）：做成"更正记录"列表，**这是页面可信度的来源，不许省略**。
9. **外部参照项目**：uSDX、mcHF、QCX、SoftRock、Hermes-Lite、KiwiSDR、TX-500、UHSDR/OVI40。
   只列附件里已核的架构事实；性能数字一律带"外部断言，未复核"角标；
   **特别注明**：#16 里没人说过"UHSDR 有非常棒的前端设计"，原话只有
   *"Andreas DF8OE has already implemented the HMC1023 in his UHSDR"*——不许把评价写成引文。
10. **页脚**：许可证（MIT，作者 2026-11-03 原话 *"The MIT license is official — fully open"*）、
    仓库与 fork 链接、**"本页由 AI 辅助整理，全部断言可按 §号回查"**、最后更新日期。

### C. 内容硬规则（违反一条就算不合格）

1. **每个数字与每句引文旁边必须有可查来源**：用 `data-source="PSDR-chronicle.md §第一纪补"`
   这类属性或脚注标出，页面上可见（鼠标悬停或小角标都行）。
   **禁止联网补充素材**；附件里没有的内容一律不写。
2. **口径不许混**：`读得`（表格/网表/页面直读）、`算得`（公式推）、`待测`（未做）三种必须区分显示。
   不许把 `算得` 显示成仪表盘读数。
3. **三条禁区**：① 不放替代件/国产化的**具体候选清单与报价**（只留 fork）；
   ② 不冒充官方（标题、域名、措辞不得暗示这是作者本人的站点；必须是"fan-made/第三方整理"）；
   ③ 不写"修好了/能用了/性能提升"这类没有实测支撑的话。
4. 引用他人原话保持**英文原样**（含错拼），署名 + 日期 + issue/commit 号；中文只做解释。
5. 只允许链接这些域名：`github.com`（本项目仓库与 PR/commit/issue）、`hackaday.io/project/1538-portablesdr`、
   以及附件里**明确记录过可达**的厂商链接。禁止链到"据说存在"的 PDF；
   已知 404/429 的链接可以写"取不到"，但**不要做成可点的有效链接**。
6. 隐私：只用 GitHub 用户名；不出现邮箱、真名、住址、台站呼号（除非附件里已公开且与本任务无关的不要主动挖）。
7. 不改动任何仓库文件；不建 issue、不发 PR、不在任何平台发帖。你只交付网站文件。

### D. 工程与设计规格

* **纯静态**：单个 `index.html`（内联 CSS + 少量原生 JS），**无构建、无框架、无外部 CDN**；
  字体用系统栈（CJK 用 `system-ui, "PingFang SC", "Microsoft YaHei", sans-serif`）。
* **性能预算**：HTML ≤ 300 KB；不引图片，示意图用内联 SVG；JS ≤ 20 KB；首屏不依赖 JS 渲染正文。
* **响应式 + 可访问**：≥ 480px 可用；时间线在键盘上可 Tab 到每个节点；正文对比度达 WCAG AA；
  `<article>/<time>/<ol>` 语义标签；提供"仅文本"可打印样式。
* **深浅色**跟随 `prefers-color-scheme`，并提供手动切换（记住偏好用 `localStorage`，不用 Cookie/网络）。
* **中英处理**：正文中文为主，历史引文保留英文原文。若时间允许做一个语言开关，
  但**不许为了翻译改动引文**。
* **数据可视化只用附件里的真数**：年表、`124/391/267` 影响圈条图、
  `#1…#21` 的 issue/PR 状态表（open/closed/merged）。没有的图不要造。
* 页内锚点导航（章节 ≥ 8 个），并提供"跳到诚实清单"的显眼入口。

### E. 交付与自检（必做，不许只交 HTML）

1. 交付：`index.html`（+ 若有独立 CSS/JS 就一并给），外加一份 `SELFTEST.md` 说明你自查了什么。
2. 自检脚本（Python 或 Node 都行，随交付附上）至少断言：
   * 页面上出现的每个数字，都能在附件里找到同串（可用简单字符串匹配 + 例外白名单）；
   * 每条 `<blockquote>` 或引文元素都带来源属性；
   * 不出现禁区词：**"替代件清单/国产型号/降本报价/性能提升/已修复/官方站点"**；
   * 所有外链域名在白名单内；
   * HTML 能被解析且无未闭合标签（用现成解析器，不用肉眼）。
3. 自检结果按**事实级**报告（通过 X 条 / 失败 Y 条 / 跳过 Z 条并说明为什么），
   **不要用"综合评分"或"完成度百分比"代替**。任何没做到的必须明说。
4. 最后给一段中文的"发布前须知"：这是第三方整理页、含 AI 辅助、且页面里没有任何实测数据。

### F. 如果你不能上传附件

把 A 档五份文件按顺序分段贴给你（每段前保留它的标题行）。优先贴 `PSDR-chronicle.md` 与
`README.fork.md`（叙事 + 边界），其次 `PSDR-upstream-threads.md` 里**你打算引用的那几条**
（按 `## #N` 小节切，别整份 87 KB 一次贴）。缺哪份就问委托方要，**不要联网找替代材料**。
